Your Cloudflare account and deploy key

About 15 minutes on a computer. You create the account, give it a payment card for file storage, make one key for the deploy, and lock that key inside GitHub. Nobody else, me included, ever sees the key.

Cloudflare

Part 1 · Create the account

  1. Open dash.cloudflare.com/sign-up in a new tab.

  2. Sign up with your own email and a strong password you keep to yourself. Confirm the email Cloudflare sends you.

  3. If Cloudflare asks what you want to do or which plan, choose the Free plan. You do not need to add a website or domain; skip that if it is offered.

Tip: turn on two-step sign-in later under your profile. It protects the account that holds the school's data.
Cloudflare

Part 2 · Get your free web address and Account ID

  1. In the left menu, open Workers & Pages.

    Compute (Workers)›Workers & Pages

    The first visit gives your account its free address ending in workers.dev. That is all this step needs; you do not create anything here.

  2. On the same page, find Account details and press the copy button next to Account ID. Paste it into a note for a few minutes. It is not secret.

Can't see it? On the account home page, the menu next to your account name also has Copy account ID. Menu names move from time to time; the Account ID is always a long string of letters and numbers.
Cloudflare

Part 3 · Turn on file storage (your choice A)

  1. In the left menu, open R2 object storage.

    Storage & databases›R2 object storage

  2. Cloudflare asks you to subscribe to R2 and add a payment method. Add your card and confirm. The plan is free up to 10 GB stored and downloads are free.

  3. Do not create a bucket. The deploy creates it with the right name. Leave this page.

What the card is for: nothing is charged while the school stays inside the free lines. Your owner home page in LMS Lego shows storage and daily use against those lines, so you see any approach long before it matters.
Cloudflare

Part 4 · Make the deploy key

  1. Open your profile, then API Tokens.

    Profile icon (top right)›My Profile›API Tokens

    Or open dash.cloudflare.com/profile/api-tokens.

  2. Press Create Token. Next to the template Edit Cloudflare Workers, press Use template.

  3. Under Permissions, press + Add more and set the new row to Account, D1, Edit. Check the list also shows Workers R2 Storage · Edit; the template normally includes it. If it is missing, add it the same way.

  4. Under Account Resources, choose Include and your account. If Zone Resources is shown, leave All zones from an account with your account. You have no website, so it grants nothing extra.

  5. Press Continue to summary, then Create Token. Press Copy on the token. Cloudflare shows it only once. Keep this tab open until Part 5 is done.

The key mayWhy the deploy needs it
Workers Scripts · EditUpload LMS Lego and switch it live (in the template)
Workers R2 Storage · EditCreate the file bucket for PDFs and images (in the template)
D1 · Edit (you add this)Create the database and apply its updates
Other template rowsHarmless for this account; you may leave them
Never paste the key into a chat, an email or a document, including this conversation. If it ever leaks, return to API Tokens and press Roll or Delete on it, then make a new one.
GitHub

Part 5 · Lock the key inside GitHub

  1. Open the repository's secret settings.

    github.com/Shegazy003/LMS_LEGO›Settings›Secrets and variables›Actions

    Or open the Actions secrets page directly.

  2. Press New repository secret. Name it exactly:

    CLOUDFLARE_API_TOKEN

    Paste the token from Part 4 into Secret and press Add secret.

  3. Press New repository secret again. Name it exactly:

    CLOUDFLARE_ACCOUNT_ID

    Paste the Account ID from Part 2 and press Add secret. You should now see both names listed; GitHub never shows the values again.

Now close the Cloudflare tab with the token and delete the note with the Account ID. The key lives only in GitHub, where the deploy reads it without printing it.
